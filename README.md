# 线索证据台 · Evidence Desk

**把分散的企业资料，整理成下一位同事接得住的线索。**

面向增长运营的业务系统交互原型：企业队列 → 原文支撑 / 来源有效性 → 人工结论 → 模拟交接或退回补证。非研发赛道，单人作品；从文档骨架 `v0` 开始新增实现。

> 内置企业、证据和交接均为虚构。导入文件只在本机处理，不调用模型、不上传、不连接生产系统。

## 立即运行

需要 Node.js 22 或更新版本。运行本体没有第三方依赖，无需密钥或数据库。

```bash
git clone https://github.com/WELT5350/1024-prototype.git
cd 1024-prototype
npm start
```

浏览器打开 **http://127.0.0.1:4173**。使用原生 ES Modules，请通过本地 HTTP 服务运行，不能直接双击 HTML。

Windows 也可以双击 [start.cmd](start.cmd)，它会启动仅监听本机的服务。保持该窗口打开，结束时 Ctrl+C。

## 先试这四步

1. 打开“星屿软件（虚构）”：两条原文分别对应具体业务用途和模型 API 接入，点击核查项下的证据编号可回看原文。
2. 点“按核查项填写草稿”，核对后“保存核查结论”；再“模拟交接”，填写负责人和下一步说明。
3. 选择“澄野数据（虚构）”：**3/3 项原文有支撑，来源日期仍待核**。补齐日期后，查看字段对照：事实支撑没有增加，来源有效性改变，旧人工结论撤回。重新核对后确认。
4. 打开“批次进度”：看到的是同一批次当前状态；新增商机显示未知，不把“已模拟接收”算成商机。

**三个产品细节**：原文支撑与来源有效性分开显示；补证前后能核对实际字段及建议变化；三行交接卡带证据编号、人工状态和未知项，可复制、下载并带入交接说明。无实际修改时保留原结论。

还可试“青禾设计”：招聘仅要求使用 AI 工具，规则建议暂缓。“雾海网络”是过期来源，“远汐人才”是代招主体不明，“岛川智能”是日期与正文冲突。

## 数据操作

**导入 CSV**：在界面下载带虚构示例的模板。按“去重标识”合并企业，按原文链接、标题、日期与摘录识别重复证据。整份文件校验通过后才保存；错误行会提示位置，原批次不变。已有企业出现新证据会撤回旧核查与交接状态，历史记录保留。不要把模板里的样本当成实际线索。

**补充 / 编辑证据**：填写已取得的原文、来源与日期，由人工标记支撑项和主体对应关系。系统只检查结构、时间和已填写的判断条件，不会自动验证原文真假。

**JSON 备份**：保存当前完整批次、证据、结论和操作记录。恢复前先校验并再次确认，替换前保留一份本机旧存储。重要操作后请下载备份，不依赖浏览器缓存长期保存。

**证据包 / CSV**：三行交接卡可复制或下载 TXT；单家 Markdown 证据包包含三行卡、依据、出处、缺失项和交接说明；批次结果 CSV 也包含三行卡。CSV 导出对可能被表格软件执行的公式文本加保护。

**数据与安全边界**：本地存储不加密，不适合多人共同使用，也不适合作为真实客户数据的生产存储。默认不联网；链接只显示为引用，不自动加载。服务只公开应用源码与演示资源，`.git`、`.work` 和私有资料不通过本地服务提供。没有用户权限、身份认证、实际通知、CRM 同步或自动采集。

## 已知限制

- 确定性规则整理人工填写的字段，不使用大模型推理或真假核验。
- 招聘 120 天、其他来源 365 天是演示观察窗口，不是生产评分规则。默认演示观察日固定为 2026-10-24，恢复自定义批次时保留其观察日。
- 一次一个批次、一个浏览器存储。跨标签页修改会暂停旧页面写入，需刷新或恢复备份。
- “候选”只表示值得进一步核实，“模拟接收”只表示本地记录；不代表预算、采购意愿、线上评分或商机。
- 业务价值是待验证的假设，未声称提升了真实转化率。生产接入需单独的需求确认、权限设计和服务端方案。
