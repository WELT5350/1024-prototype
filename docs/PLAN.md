# 实施计划与验收

本次交付：**线索证据台**，面向增长运营的本地可交互原型。把一条分散的企业线索整理成能复核、能补证、能交接的证据包。产品方向为本次原型的设计假设，不代表部门已批准立项。

## 为什么选它

三个候选中，证据台直接处理“这家公司做什么、依据是什么、还缺什么、下一步由谁处理”。标准核查嵌入详情，批次进度用于回看，避免做三个互不相干的系统。业务价值假设是减少核查时反复切换资料、避免把缺证据当无需求、提高交接信息完整度；尚未经过真实用户效能实验，不声称提升了转化率。

## 计划

1. **资料与边界**：核对原始 PDF；标记初始文档基线；建立计划与 draft PR。完成标准：要求、假设、验收项可追踪。
2. **核查主流程**：队列 → 证据原文 → 四项标准 → 人工判断 → 本地交接记录。完成标准：候选、待核实、暂缓、退回补证都可演示，变更刷新后保留。
3. **使用与恢复**：本地 CSV 导入、校验与去重；JSON 备份恢复；CSV/Markdown 交接包导出；批次概览和空状态。完成标准：错误输入不破坏已有数据，存储失败有提示。
4. **验证与交付**：规则单测、浏览器流程测试、手机/键盘检查、录制实际操作视频、架构与演示讲稿、PR 校验。完成标准：全套检查通过，源码和视频可下载，运行命令可复现。

## 产品范围

- 内置全为明确标注的虚构企业、原文和时间；仅作演示。
- 四项核查：主体对应、用途具体、来源与日期完整、模型服务关系合理。结论可解释，缺失项明确；不以命中工具名或堆来源类型自动判定需求。
- 不复制任何生产系统评分阈值、权重或客户名单；不把本地核查冒充线上评分。
- 一次只管理当前批次；所有进度使用当前批次分母，未连接的商机结果显示未知。
- 交接、退回是浏览器里的模拟协作记录，不发送给销售或 CRM。
- 浏览器只读写本机存储，无登录、无外部 API、无模型计费、无自动采集、无上传。

## 验收重点

- 过期、日期冲突、招聘仅技能要求、猎头归属不明等情况不会自动变成候选。
- 人工覆盖建议必须写原因；交接必须先完成核查且有负责人；退回必须有补证项。
- 导入保留引用文本，防止 HTML 执行和 CSV 公式注入；不联网取 URL。
- 本地存储损坏不静默重置；提供恢复和重置入口。
- 演示视频展示实际界面操作，注明虚构数据和原型边界。
