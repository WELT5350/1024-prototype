# AI 使用与创作过程

## 人提出的问题

将真实工作中“线索为什么值得核实、缺什么、如何交接”的问题做成部门业务系统原型。Welt 提供了业务背景、资料和比赛要求，由 AI 完成方案整理、实现和验证。最终是否符合部门需求仍由 Welt 评审。

## 本次取舍

- 三个候选中先实现证据台，将标准检查、批次进度做成辅助页面；不同时做三个庞大系统。
- 面向核查与交接的信息质量，而非另建生产评分平台。不复制内部生产评分配置。
- AI 用于资料阅读、设计、实现、回归验证、录制和文档。原型使用确定性规则，不调用模型推断企业需求。
- 用原生模块完成原型，运行本身零第三方依赖。虚构数据覆盖会误判的情况，测试针对业务边界。

## 过程证据

Git 历史按阶段持续提交，全部进入同一条工作 PR，而非最后一天一次性推送。初始文档骨架标记 `v0`；第一个提交先记录计划与边界，然后提交实现与测试，最后提交验证和演示。提交和验证结果可在 Git 记录中复查，未测量开发速度提升倍数。

验证入口：`npm run check`、`npm run test:ui`；具体实测记录见 `VALIDATION.md`。演示录制脚本可审查并重跑。自动检查能验证数据与交互一致性，不能证明真实客户需求、生产商业价值或模型判断准确率。

## 曾纠正的问题

- 不将不同时期的批次混为同一漏斗，不将未知后段结果写成 0。
- 不把多来源凑齐当采购需求，不把 AI 工具使用技能当组织级模型服务需求。
- 交付代码、截图和视频统一使用虚构样本。

## 未声称做到

未调用 AI 对企业真假进行核验，未联系企业或销售，未连接 CRM，未证明提高真实线索转化率，未确认部门已批准原型立项。用户可在可运行的结果上评审设计假设。
